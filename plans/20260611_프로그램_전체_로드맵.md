# 프로그램 전체 로드맵 및 점검 기록

작성일: 2026-06-11

## 1. 프로그램 정체성

이 프로젝트는 유튜브 쇼츠/롱폼 콘텐츠 제작을 위한 로컬 AI 제작 도구다.

핵심 목적은 다음 흐름을 한 화면에서 처리하는 것이다.

1. 주제/장르/타겟 연령 입력
2. 쇼츠 대본 또는 롱폼 챕터 생성
3. 대본을 씬 단위로 분해
4. 캐릭터/의상/배경/카메라 규칙을 반영한 이미지 프롬프트 생성
5. Gemini/ChatGPT/Claude/Genspark/Grok 등 외부 AI 서비스에 프롬프트 전송
6. 이미지/영상 결과 저장
7. 생성 히스토리, 스타일 템플릿, 캐릭터/의상 프리셋 관리

기술 스택은 Vite + React(TypeScript) 프런트, Express(Node) 백엔드, Puppeteer 자동화, jsonrepair 기반 JSON 복구, 파일 시스템 기반 저장 구조다.

실제 `package.json` 기준 현재 상태는 다음과 다르다.

- 패키지 버전: `2.5.2`
- React: `19.2.0`
- 서버 포트: `3002`
- 주요 앱: 쇼츠랩, 쇼츠 생성기, AI Studio, 씨네보드, 롱폼, 템플릿 분석, 유튜브 검색이 한 루트 앱에 통합됨
- 현재 운영상 가장 중요한 축은 AI Studio 단독이 아니라 `쇼츠랩 + 대본/이미지 프롬프트 생성 + 파일 저장/자동화`

README는 최신 기능 기준으로 전면 갱신이 필요하다.

## 5. 대본 생성 흐름

### 일반 스토리 생성

1. `UserInput` 생성
2. `generateStory`에서 엔진 프롬프트, 장르, 템플릿, 타겟 연령, 의상/캐릭터 규칙 조합
3. `/api/generate` 호출
4. 서버가 Puppeteer로 선택 AI 서비스에 전송
5. 서버에서 JSON 추출/복구
6. `StoryResponse` 반환
7. 프런트 히스토리와 서버 파일에 저장

### 쇼츠랩 AI 줄거리 생성 경로

1. `AI 줄거리 생성`
2. `generateBenchmarkStorylinePackage`로 줄거리 후보 생성
3. 사용자가 줄거리 선택/수정
4. `이 줄거리로 대본 생성`
5. `buildLabScriptOnlyPrompt`로 대본만 생성
6. 입력란에 대본 반영
7. 사용자가 별도로 `씬 분해 & 프롬프트 생성`

이 경로의 장점은 대본 품질을 먼저 잡고, 이미지 프롬프트는 별도 단계에서 통제할 수 있다는 점이다.

### AI 마스터 생성 경로

1. `AI 마스터 생성`
2. `buildSimplifiedMasterPrompt`
3. LLM이 대본, 씬 구조, lockedOutfits 일부를 한 번에 생성
4. 로컬에서 의상/캐릭터 맵 보정
5. 미리보기 씬 생성
6. 필요 시 `캐릭터 정보 적용`

이 경로는 빠르지만, 대본 품질과 이미지 프롬프트 품질을 동시에 LLM에 맡겨 흔들림이 크다.

## 6. 이미지 프롬프트 생성 흐름

주요 빌더는 `services/labPromptBuilder.ts`다.

담당 범위:

- 장르별 스토리 지침
- 타겟 연령 변환
- 캐릭터 슬롯 규칙
- 여성/남성 의상 선택
- 겨울 악세서리
- 카메라 앵글/샷 타입
- POV 규칙
- negativePrompt
- longPrompt/shortPrompt 품질 태그
- 캐릭터 identity/hair/body/outfit 고정

핵심 문제는 이 파일이 너무 많은 책임을 가진다는 점이다. 장기적으로는 아래처럼 분리하는 것이 좋다.

- `scriptPromptBuilder`: 대본 전용
- `scenePromptBuilder`: 씬 분해 전용
- `visualPromptBuilder`: 이미지 프롬프트 전용
- `characterSlotService`: 캐릭터 슬롯/정규화 전용
- `outfitAssignmentService`: 의상 선택/중복 방지 전용
- `jsonContract`: LLM 출력 스키마 전용

## 7. LLM 응답 파싱 흐름

현재 JSON 파서는 여러 곳에 중복되어 있다.

- `server/index.js`
- `services/jsonParse.ts`
- `utils/jsonParser.ts`
- `App.tsx`
- 일부 컴포넌트 내부 직접 파싱

일반적인 복구 절차는 다음과 같다.

1. 코드블록 제거
2. JSON 객체 범위 추출
3. 내부 따옴표/개행 보정
4. `JSON.parse`
5. 실패 시 `jsonrepair`
6. 그래도 실패하면 정규식 fallback

문제는 경로마다 “첫 JSON 블록을 잡는지”, “마지막 완성 블록을 잡는지”, “어떤 키를 보호하는지”가 다르다는 점이다. 같은 LLM 응답도 버튼/경로에 따라 다르게 파싱될 수 있다.

## 9. 현재 확인된 주요 문제

### 보안/운영

- `/api/auth/gemini-key`가 서버 API 키를 클라이언트로 반환한다.
- `/api/history` POST가 검증 없이 전체 `history.json`을 덮어쓴다.
- 일부 파일명/sessionId/templateId 파라미터에 path traversal 방어가 약하다.
- `/api/generate`가 `보낸대본.txt`, `받은대본.txt`를 프로젝트 루트에 저장한다.
- Puppeteer auto-launch가 기본 활성화라 브라우저 세션/프로필 락/메모리 점유 문제가 생길 수 있다.

### 코드 구조

- `ShortsLabPanel.tsx`가 지나치게 비대하다.
- `server/index.js`에 API가 너무 많이 집중되어 있다.
- `http://localhost:3002` 하드코딩 호출이 많다.
- JSON 파서가 중복되어 결과 일관성이 떨어진다.
- 이미지 생성 경로가 `이미지 생성`과 `AI 생성`으로 나뉘는데 UI 라벨만으로 차이가 불명확하다.

### 백엔드/API

- `/api/genre-guidelines`, `/api/video/refine-prompt`, `/api/video/generate-smart` 중복 라우트가 있다.
- ES Module 환경에서 `require('os')` 사용 흔적이 있어 특정 API에서 런타임 오류 가능성이 있다.
- `/api/generate/raw` 호출부는 `maxTokens`, `temperature`를 보내지만 서버 계약이 명확하지 않다.
- 대용량 base64 JSON body와 동기 파일 I/O가 많아 배치 이미지/영상 생성 시 이벤트 루프 블로킹 가능성이 있다.

## 10. 쇼츠랩 3개 생성 버튼 집중 점검

마마님이 자주 쓰는 쇼츠랩 생성 버튼 3개는 현재 성격이 명확히 다르다.

### 10.1 AI 줄거리 생성

의도:

- 먼저 좋은 줄거리 후보를 여러 개 만든다.
- 사용자가 고른 줄거리로 대본을 생성한다.
- 이후 씬 분해/이미지 프롬프트를 별도 단계에서 만든다.

현재 본파일 실제 흐름:

- `handleGenerateStorylines`
- `generateBenchmarkStorylinePackage`
- `handleConfirmStoryline`
- `handleAiGenerateWithContext`
- `buildLabScriptOnlyPrompt`

장점:

- 대본 품질을 따로 관리하기 좋다.
- 벤치마킹 설명을 구조만 참고하게 만들 수 있다.

문제:

- 줄거리 생성과 대본 생성은 분리되어 있지만, 이후 씬 분해/프롬프트 생성까지 자동 품질 관리가 이어지지 않는다.
- `generateBenchmarkStorylinePackage` 내부 JSON 파싱에 브라우저 ESM과 맞지 않는 `require('jsonrepair')` 흔적이 있다.

### 10.2 AI 마스터 생성

의도:

- 대본, 씬, 캐릭터, 의상 맵을 한 번에 빠르게 만든다.

현재 본파일 실제 흐름:

- `handleMasterGenerate`
- `buildSimplifiedMasterPrompt`
- `/api/generate/raw`
- JSON 파싱
- `rebalanceMasterSceneCharacterMix`
- 의상 맵/캐릭터 프로필 생성
- 씬 미리보기 반영

문제:

- 대본 품질과 이미지 프롬프트/씬 구조 품질을 한 번에 LLM에 맡겨 결과가 흔들린다.
- `AI 줄거리 생성`의 장점인 “먼저 좋은 줄거리/대본을 만들고, 그 다음 시각화” 흐름을 타지 않는다.
- 후처리에서 캐릭터/의상/씬 배정이 많이 보정되기 때문에 LLM 출력과 최종 프롬프트 사이의 추적이 어렵다.

### 10.3 AI MASTER V4 생성

마마님 설명 기준 의도:

- `AI 줄거리 생성`의 로직을 따르면서,
- 대본 품질과 이미지 프롬프트 품질을 높이기 위한 개선형 경로.
- 즉, “줄거리/대본 우선 -> 슬롯 기반 씬 배정 -> 로컬에서 정교한 이미지 프롬프트 재조립”이 되어야 한다.

현재 본파일 실제 상태:

- `ShortsLabPanel.tsx`에 `runShortsLabV4Master` import가 있다.
- 그러나 정식 경로 `services/shortslab-v4/shortsLabV4FlowService.ts`가 현재 존재하지 않는다.
- `handleMasterGenerateV4`는 `showToast('AI MASTER V4 시작')`만 실행하는 stub이다.
- 따라서 현재 V4 버튼은 의도한 V4 파이프라인을 실행하지 못한다.

백업 파일에서 확인된 V4 의도:

- `components/ShortsLabPanel.tsx.bak_v4_connect`에는 더 완성된 V4 흐름 흔적이 있다.
- 흐름은 다음과 같았다.
  1. 줄거리 자동 생성 또는 선택된 줄거리 사용
  2. `buildLabScriptOnlyPrompt`로 대본만 생성
  3. `buildV4SceneAssignmentPrompt`로 고정 슬롯 목록 안에서 씬별 characterIds만 배정
  4. 의상은 로컬 규칙 또는 토글에 따라 배정
  5. `parseJsonToScenesDirect`로 기존 정교한 rebuild를 활용해 최종 씬 생성

현재 문제 결론:

- V4는 “엉뚱한 AI 마스터 생성 로직을 탄다”기보다, 본래 V4 연결 파일/핸들러가 본파일에 제대로 남아있지 않아 의도한 줄거리 기반 V4 경로가 유실된 상태다.
- 백업 기준 V4는 AI 마스터와 달리 `buildSimplifiedMasterPrompt`를 타지 않고 `buildLabScriptOnlyPrompt` 기반이어야 한다.
- 정식 구현 시 `AI 줄거리 생성`과 `V4`를 연결하려면 `handleConfirmStoryline`도 `handleAiGenerateWithContext` 대신 V4 경로를 선택적으로 타게 할지 결정해야 한다.

## 11. V4 재설계 권장안

목표:

`AI 줄거리 생성`의 장점과 `AI 마스터 생성`의 자동화를 합친다.

권장 파이프라인:

1. 줄거리 생성/선택
2. 대본 전용 프롬프트로 대본만 생성
   - `buildLabScriptOnlyPrompt`
   - LLM에는 이미지 프롬프트를 만들지 못하게 제한
3. 씬 배정 전용 프롬프트로 `scriptLine`, `characterIds`, `cameraAngle`, `action`, `background`만 생성
   - 의상/몸매/헤어/최종 longPrompt는 LLM에게 맡기지 않음
4. 로컬 코드에서 캐릭터 규칙, 저장 캐릭터, 의상 맵, 악세서리, 배경 고정 규칙을 재주입
5. `applyCharacterInfoToScenes` 또는 V4 전용 direct parser로 최종 이미지 프롬프트 생성
6. prompt diff 리포트 저장
7. 미리보기 반영

V4에서 금지해야 할 것:

- `buildSimplifiedMasterPrompt` 사용 금지
- LLM이 최종 longPrompt 전체를 임의 작성하게 하는 것 금지
- LLM이 캐릭터 identity/hair/body/outfit을 새로 지어내는 것 금지
- 캐릭터 슬롯을 rebalancing으로 임의 교체하는 것 최소화

V4에서 허용할 것:

- 줄거리/대본 창작
- 씬별 등장 슬롯 배정
- 카메라/행동/표정/배경의 초안
- 단, 최종 프롬프트는 로컬 규칙으로 재조립

## 15. AI 줄거리 생성 실제 13단계 흐름과 V4 적용 계획

이 장은 쇼츠랩에서 가장 품질을 높여야 하는 핵심 흐름이다. 목표는 기존 `AI 줄거리 생성`의 장점인 안정적인 기획/대본 단계를 유지하면서, 후처리 파싱과 이미지 프롬프트 조립을 V4 독립 파이프라인으로 분리하는 것이다.

### 15.1 현재 실제 13단계 흐름

1. 주제 입력, 장르 선택, 타겟 연령 선택
2. `AI 줄거리 생성` 클릭
3. LLM에 "줄거리 10개"만 요청
4. 사용자가 줄거리 하나 선택
5. `이 줄거리로 대본 생성` 클릭
6. 선택한 줄거리를 추가 컨텍스트로 넣어서 "대본만" 다시 생성
7. 생성된 대본이 입력창에 들어감
8. `씬 분해 & 프롬프트 생성` 클릭
9. 대본을 다시 LLM에 보내서 인물 추출
10. 인물 슬롯 매핑
11. 대본을 다시 LLM에 보내서 씬/이미지 프롬프트 생성
12. 로컬 후처리에서 캐릭터, 의상, 배경, 카메라를 다시 조립
13. 최종 미리보기 탭에 들어감

### 15.2 현재 흐름의 핵심 문제

- 2단계 `AI 줄거리 생성`은 현재 `aiTargetAge`, `aiGenre`, `settings.koreanGender`를 직접 전달하지 않는다. 줄거리 10개는 주제/벤치마크 중심으로만 생성된다.
- 6단계 대본 생성에서야 타겟 연령/장르/성별이 반영된다.
- 9~11단계에서 LLM을 다시 호출하며 인물 추출과 씬 분해를 새로 하므로, 앞에서 만든 줄거리/대본의 인물 구성이 흔들릴 수 있다.
- 10단계 슬롯 매핑은 이름 추출 결과에 의존한다. LLM이 이름을 누락하거나 조연을 추가하면 `WomanA`, `WomanB`, `ManA` 배정이 밀릴 수 있다.
- 12단계에서 `rebalanceMasterSceneCharacterMix`가 멀티샷 비율을 맞추려고 원래 `characterIds`에 없는 인물을 추가할 수 있다.
- 12단계에서 첫 번째 배경을 모든 씬 배경으로 강제 적용하는 로직이 있어, 워터해저드/그린/클럽하우스/석양 같은 장면별 핵심 배경이 사라질 수 있다.
- 12단계 의상 처리는 LLM `lockedOutfits`, `longPrompt`에서 추출한 `wearing`, 의상 리스트 fallback이 섞인다. 따라서 `의상 LLM 선택`/`의상 랜덤 선택` 토글 계약이 명확하지 않다.
- 최종 미리보기 직전 검증이 없어 `scriptLine`, `characterIds`, `longPrompt`의 인물 수/행동/소품 불일치가 그대로 표시된다.

### 15.4 과거 V4 설계의 의도

과거 V4 계획서의 핵심 문장:

> "주제 입력 -> 버튼 한 번"으로, 캐릭터/의상/배경/얼굴이 모든 장면에서 100% 일관된 고품질 대본 + 이미지프롬프트를 생성한다. 일관성은 LLM의 선의가 아니라 코드 구조로 강제 보장한다.

V4 설계는 기존 `AI 마스터 생성`처럼 한 번에 대본과 이미지 프롬프트를 모두 LLM에게 맡기는 방식이 아니다.

의도한 V4 단계:

1. 줄거리: `generateBenchmarkStorylinePackage` 재사용
2. 대본: `buildLabScriptOnlyPrompt` 재사용
3. 캐릭터 확정: 고정 슬롯 + `characterId` 잠금
4. 씬 배정: LLM은 고정 슬롯 목록 중 `characterIds`와 action만 선택
5. 조립: 코드가 외모/의상/배경/카메라/최종 이미지 프롬프트를 생성

V4에서 금지해야 할 것:

- `rebalanceMasterSceneCharacterMix` 호출
- LLM이 새 캐릭터 슬롯을 임의 생성
- LLM이 최종 캐릭터 외형 문구를 매 씬 새로 작성
- LLM이 의상 문자열을 씬마다 바꿔 쓰기
- 이전 폴더/이전 `prompts.json`/이전 의상 캐시 재사용

V4에서 보장해야 할 것:

- 같은 `slotId`의 identity/hair/body/face는 모든 씬에서 동일
- `lockedOutfits[slotId]`는 영상 전체에서 1개 값
- `scenes[].characterIds`는 고정 슬롯 목록의 부분집합
- 대본 라인에 없는 인물은 후처리에서 추가하지 않음
- 텍스트 외형과 참조 이미지가 같은 `characterId` 기준
- 최종 미리보기 전에 검증 결과를 남김

### 15.5 V4 복원 및 개선 작업 계획

1. `services/shortslab-v4` 디렉터리를 히스토리에서 복원한다.
2. `v4CharacterText.ts`, `v4SceneFactory.ts`, `v4DirectParser.ts`를 기준으로 프롬프트 조립 로직을 분리한다.
3. `shortsLabV4FlowService.ts`는 다음 입력을 받는 오케스트레이터로 정리한다.
   - `topic`
   - `genre`
   - `targetAge`
   - `gender`
   - `selectedStoryContext`
   - `useRandomOutfits`
   - `allowedOutfitCategories`
   - `outfitsData`
4. `AI MASTER V4 생성` 버튼은 기존 `AI 줄거리 생성` 철학을 따른다.
   - 줄거리 생성
   - 선택된 줄거리로 대본만 생성
   - 고정 슬롯으로 씬 배정
   - 코드로 이미지 프롬프트 재조립
5. `AI 줄거리 생성 -> 이 줄거리로 대본 생성` 일반 경로와 V4 경로를 UI에서 명확히 분리한다.
6. V4에서는 `rebalanceMasterSceneCharacterMix`를 사용하지 않는다.
7. V4에서는 배경 고정 여부를 명시 옵션으로 둔다.
   - 기본 권장: 장면별 핵심 배경 유지
   - 선택 옵션: 1번 씬 배경으로 통일
8. V4 의상 토글 계약을 명확히 한다.
   - `의상 LLM 선택`: LLM이 캐릭터별 `lockedOutfits`만 생성하고, 코드가 전 씬에 고정 적용
   - `의상 랜덤 선택`: 의상 리스트에서 캐릭터별 1회만 선택하고, LLM 의상은 무시
9. 최종 `setScenes` 전에 V4 검증기를 둔다.
   - 씬 번호 연속성
   - 대본 라인 누락 여부
   - `characterIds`가 고정 슬롯 목록 안에 있는지
   - prompt의 Person 수와 `characterIds.length` 일치 여부
   - action에 등장하는 인물과 characterIds 일치 여부
   - 의상 문자열이 씬마다 변하지 않는지
   - 필수 소품/장소가 prompt에 반영됐는지
10. 생성 결과는 새 세션/새 폴더 기준으로 저장해 이전 결과와 섞이지 않게 한다.

### 15.6 최종 품질 목표

V4의 목표는 "그럴듯한 프롬프트"가 아니라 쇼츠 영상 제작에 바로 쓸 수 있는 구조화된 결과다.

- 대본은 줄거리 기반으로 자연스럽고 쇼츠 호흡에 맞아야 한다.
- 각 씬의 이미지 프롬프트는 해당 대본 라인의 인물/행동/소품/장소를 정확히 반영해야 한다.
- 같은 캐릭터는 모든 씬에서 같은 얼굴, 같은 헤어, 같은 체형, 같은 의상을 유지해야 한다.
- 의상은 토글에 따라 LLM 디자인 또는 의상 리스트 랜덤 중 하나만 사용해야 한다.
- 후처리는 LLM 결과를 보강해야 하며, 대본과 맞는 인물을 바꾸거나 없는 인물을 추가하면 안 된다.
- 미리보기는 검증을 통과한 씬만 표시하거나, 문제 씬을 명확히 경고해야 한다.

## 16. ShortsLabPanel 비대화 해결 및 V4 독립 파일화 계획

`components/ShortsLabPanel.tsx`는 현재 약 12,891줄이다. V4를 이 파일 내부 helper에 계속 의존하게 만들면 다시 `AI 마스터 생성` 계열 로직과 섞인다. V4는 패널 내부 구현을 참조하지 않고, 새 서비스 파일 안에서 독립적으로 동작해야 한다.

### 16.1 V4 분리 원칙

V4에서 금지할 참조:

- `handleMasterGenerate`
- `handleMasterStyleSceneGeneration`
- `handleMasterGenerate_OLD`
- `buildSimplifiedMasterPrompt`
- `rebalanceMasterSceneCharacterMix`
- `deriveOutfitMapFromScenePrompts`
- 패널 내부 슬롯/후처리 helper 직접 참조

V4에서 재사용 가능한 안정 로직:

- `generateBenchmarkStorylinePackage`
- `buildLabScriptOnlyPrompt`
- `parseJsonFromText`
- `getCharacterRules`
- `/api/generate/raw`
- `/api/outfits`
- `/api/save-story`

핵심 기준:

- V4는 `AI 마스터 생성`의 변형이 아니다.
- V4는 `AI 줄거리 생성` 계열 로직을 기반으로 한다.
- V4가 `buildSimplifiedMasterPrompt` 또는 `handleMasterGenerate` 흐름을 타면 실패로 본다.
- V4는 `generateBenchmarkStorylinePackage -> buildLabScriptOnlyPrompt -> V4 전용 씬 배정 -> V4 전용 프롬프트 조립` 순서를 따라야 한다.

components/shortslab-v4/

### 16.3 파일별 역할

- `v4Types.ts`
  - V4 전용 타입 정의
  - `V4Input`, `V4Storyline`, `V4ScriptResult`, `V4ScenePlan`, `V4Scene`, `V4OutfitMode`, `V4ValidationIssue`, `V4Result`

- `v4ApiClient.ts`
  - `/api/generate/raw`, `/api/outfits`, `/api/save-story` 호출 래핑
  - 패널에서 직접 fetch하지 않도록 함

- `v4StorylineService.ts`
  - `generateBenchmarkStorylinePackage` wrapper
  - 기존 줄거리 생성 로직을 따르되 `topic`, `genre`, `targetAge`, `gender` 조건을 V4 컨텍스트에 명시

- `v4ScriptService.ts`
  - 선택된 줄거리로 대본만 생성
  - `buildLabScriptOnlyPrompt` 사용
  - scenes/longPrompt/shortPrompt 생성 금지

- `v4SlotService.ts`
  - 고정 슬롯 확정
  - `WomanA`, `WomanB`, `WomanD`, `ManA`, `ManB` 같은 후보를 주제/성별/캐릭터 규칙 기준으로 잠금
  - LLM 인물 추출 의존도를 줄임

- `v4SceneAssignmentService.ts`
  - LLM에게 대본 라인별 `sceneNumber`, `scriptLine`, `characterIds`, `action`, `background`, `cameraAngle`만 받음
  - 최종 이미지 프롬프트는 받지 않거나 참고값으로만 보관
  - `characterIds`는 고정 슬롯 목록의 부분집합만 허용

- `v4OutfitService.ts`
  - 의상 토글 계약 강제
  - `LLM`: 캐릭터별 `lockedOutfits`만 생성하고 전 씬 고정
  - `RANDOM`: 의상 리스트에서 캐릭터별 1회만 선택하고 LLM 의상 무시
  - 두 모드를 섞지 않음

- `v4PromptFactory.ts`
  - 최종 이미지 프롬프트 조립 전담
  - 캐릭터 외형, 헤어, 체형, 의상, 액션, 배경, 카메라를 코드가 조립
  - 과거 `v4CharacterText.ts`, `v4SceneFactory.ts`의 좋은 부분을 선별 재사용

- `v4Validator.ts`
  - 최종 미리보기 전 검증
  - 씬 번호 연속성
  - 대본 라인 누락 여부
  - `characterIds` 허용 슬롯 검증
  - Person 수와 `characterIds.length` 일치 여부
  - 같은 캐릭터 의상/외형 일관성 검증
  - 필수 소품/장소 반영 여부 점검

- `v4PersistenceService.ts`
  - V4 결과 저장 전담
  - 새 세션/새 폴더 기준 저장
  - 이전 `prompts.json`, 이전 의상 캐시, 이전 이미지 기록과 섞이지 않도록 분리

- `v4FlowService.ts`
  - 전체 오케스트레이션
  - 패널이 호출하는 단일 진입점

### 16.4 ShortsLabPanel에 남길 최소 코드

패널은 상태를 넘기고 결과를 받는 얇은 wrapper만 가져야 한다.

```ts
const handleMasterGenerateV4 = async () => {
  setIsMasterGenerating(true);
  try {
    const result = await runShortsLabV4Flow({
      topic: aiTopic,
      genre: aiGenre,
      targetAge: aiTargetAge,
      gender: settings.koreanGender,
      selectedStoryContext: selectedStoryDraft,
      useRandomOutfits,
      service: targetService || 'GEMINI',
      imagePromptLanguage: settings.imagePromptLanguage
    });

    setScriptInput(result.scriptBody);
    setScenes(result.scenes);
    setCurrentFolderName(result.folderName);
    setActiveTab('preview');
  } finally {
    setIsMasterGenerating(false);
  }
};
```

## 17. 백업 시스템 현황과 개선 계획

현재 프로젝트에는 백업 도구가 있다.

- `bin/project-backup`
- `bin/project-backup.ps1`
- `bin/project-backup-src.ps1`
- `project-backup.bat`

하지만 현재 Linux/WSL 환경에서는 `bin/project-backup`이 `zip` 명령에 의존해서 실패할 수 있다. 실제 확인 결과 `zip: command not found`로 실패했다.

또한 전체 프로젝트를 `tar.gz`로 압축하려고 하면 `generated_scripts`, 임시 드라이브 업로드 폴더, 대용량 산출물 때문에 시간이 매우 오래 걸리고 수 GB 크기의 불완전 백업이 생길 수 있다.

이번 작업 전 조치:

- 실패한 전체 압축 백업 찌꺼기 `backups/project-backups/20260611-132929-project-backup.tar.gz` 삭제 완료
- 핵심 파일 백업 폴더 생성
  - `backups/v4-refactor-20260611-작업전/`
- 백업한 파일
  - `ShortsLabPanel.tsx.backup`
  - `20260611_프로그램_전체_로드맵.md.backup`
  - `package.json.backup`
  - `tsconfig.json.backup`

백업 시스템 개선 권장안:

1. 전체 백업과 소스 백업을 분리한다.
2. 기본 백업은 소스 파일만 포함한다.
3. `generated_scripts`, `longform_sessions`, `node_modules`, `dist`, `.git`, `.tmp.driveupload`, 이미지/영상 파일은 기본 제외한다.
4. `zip`이 없으면 `tar.gz`로 자동 fallback한다.
5. 백업 완료 후 파일 크기와 포함 파일 수를 출력한다.
6. 백업 실패 시 불완전 파일을 자동 삭제한다.
7. 작업 단위별 `backups/{작업명}-{날짜}/` 핵심 파일 백업 기능을 별도 제공한다.
