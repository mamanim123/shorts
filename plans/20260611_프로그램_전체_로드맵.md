## 0. 코드 점검으로 확정된 현재 상태

### 정상 동작 (수정 불필요)
- V4 흐름 배선 정상: handleMasterGenerateV4 -> generateV4StorylinePackage -> 줄거리 10개 -> 선택 -> handleConfirmStoryline(isV4StoryMode 분기) -> handleV4GenerateFromStoryline -> runShortsLabV4FromStoryContext

- 이름 고정 시점: 대본 생성 시점. slotId(WomanA)와 이름(rule.name)이 한 쌍으로 고정되어 씬배정/최종프롬프트까지 slotId로 추적됨. 파싱에서 새로 붙는 것이 아님.
- 이름 소스 단일화 확정: 대본 이름(getSlotNameMap)과 V4 씬배정 이름(getV4FixedSlots의 rule.name) 모두 getCharacterRules()의 rule.name을 읽음. 이름 일관성 보장됨.
- 의상: useRandomOutfits 토글로 LLM자율생성 / 리스트랜덤 완전 분리(if/else). 모드 안 섞임. 현재 기본은 LLM 자율생성.
- 의상 슬롯 필터링: resolveV4Outfits는 usedSlotIds(실제 등장 슬롯)만 사용. 정상.

## 1. 확정된 핵심 문제 3가지

### 문제 A (최우선) - 3면도 얼굴 일관성이 V4에 안 붙음
- 원인: 슬롯<->저장캐릭터 연결(characterId)이 영구 저장되지 않고 세션(characterCastings, masterCharacterProfiles)에만 존재.
- CharacterSlotRule 타입/저장 로직에 characterId 필드 없음. importCharacter는 face/hair/body 텍스트만 복사하고 characterId는 안 남김.
- 결과: 새로고침 또는 V4 신규 실행 시 슬롯-캐릭터 연결 소실 -> characterCastings.get(charId)가 비어 if(!casting) return으로 조용히 스킵 -> 3면도 없이 텍스트로만 이미지 생성.
- V4 buildV4Scenes(v4PromptFactory)는 face/hair/body 텍스트만 prompt에 박고, 참조 이미지(referenceImageUrls) 연결 없음.

### 문제 B - 유령 슬롯
- 원인: getV4FixedSlots(v4SlotService)가 getCharacterRules의 등록 캐릭터 전원을 슬롯으로 생성(WomanA~G 등).
- 결과: 씬배정 프롬프트에 대본에 없는 WomanE/F/G까지 들어가 LLM 혼란.
- 대조: 의상 단계는 usedSlotIds만 넘겨 깨끗함. 두 단계 필터 기준 불일치.

### 문제 C - 의상 설명 과다 길이 (낮은 우선순위)
- LLM 의상 설명이 50단어 초과. 외형+의상 합치면 씬 프롬프트가 과도하게 길어져 이미지 AI가 핵심 놓칠 수 있음.

## 2. 작업 계획 (우선순위 순)

### STEP 1 - characterId 영구 저장 (문제 A의 토대)
1. types 또는 shortsLabCharacterRulesDefaults의 CharacterSlotRule 인터페이스에 characterId?: string 필드 추가
2. normalizeCharacterSlot에서 characterId 보존하도록 추가
3. applyCharacterToMasterProfile(ShortsLabPanel.tsx 6049)에서 updateCharacter(gender, slotId, { characterId: char.id }) 호출하여 서버 규칙에 영구 저장
4. 검증: 드롭다운(8499)에서 슬롯에 캐릭터 지정 후 새로고침 -> 연결 유지되는지 확인

### STEP 2 - V4 생성 후 3면도 로드 (문제 A 본체)
1. runShortsLabV4FromStoryContext 결과 수신 후, handleV4GenerateFromStoryline에서
2. result.scenes의 usedSlotIds 각각에 대해 rule.characterId로 savedCharacters에서 캐릭터 조회
3. applyCharacterToMasterProfile(또는 동일 로직)로 characterCastings에 3면도(referenceImageUrls front/angle45/back) 로드
4. 검증: V4 생성 후 이미지 생성 시 referenceImages가 채워지고(2834~) 3면도가 reference로 넘어가는지 확인

### STEP 3 - 유령 슬롯 필터링 (문제 B)
1. getV4FixedSlots에 상한 또는 대본 등장 인물 필터 적용
   - 방법: 대본 본문에 rule.name이 실제 등장하는 슬롯 + 내레이터 슬롯 + (골프면 캐디) 만 남김
2. 씬배정 프롬프트 슬롯 목록을 추려 LLM 혼란 제거
3. 검증: 씬배정 프롬프트에 대본 미등장 슬롯이 안 들어가는지 확인

### STEP 4 - 의상 설명 길이 제한 (문제 C, 선택)
1. v4OutfitService의 buildV4LlmOutfitPrompt 규칙에 "의상 설명은 15단어 이내 핵심 키워드" 추가
2. 또는 normalizeOutfitMap에서 길이 트림

## 3. 작업 원칙
- V4는 buildSimplifiedMasterPrompt / handleMasterGenerate / rebalanceMasterSceneCharacterMix 사용 금지 유지
- 각 STEP 전 핵심 파일 백업(.bak)
- 각 STEP 후 npm run build 로 타입/import 검증
- 파일 저장은 BOM 없는 UTF-8
