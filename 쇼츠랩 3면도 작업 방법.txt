쇼츠대본생성기 v3.5.3 — 캐릭터 관리 통합 작업 문서
1. 작업 배경과 목표
이 프로젝트의 캐릭터 관리는 여러 곳에 흩어져 있어 혼란이 컸다. 캐릭터 정보가 서버 폴더, 브라우저 localStorage, 장르매니저 의상규칙 등 여러 데이터 소스에 중복·분산되어 있었고, 한쪽을 수정해도 다른 쪽에 반영되지 않았다. 3면도(정면/45도/뒷모습) 이미지는 별도 화면(AI Studio)에서만 만들 수 있었고, 캐릭터의 텍스트 속성(헤어/체형/스타일)과 연결되지 않았다.

최종 목표는 캐릭터의 생성/수정/삭제와 3면도 생성을 한곳에서 처리하고, 그 데이터가 모든 곳에 일관되게 반영되도록 만드는 것이었다. 작업 도중 사용자 결정에 따라, 최종적으로 "캐릭터는 무조건 장르매니저의 의상규칙에서만 다룬다"로 방향이 확정되었다.

작업 환경은 두 PC를 오갔다. 회사 PC는 F:\test\쇼츠대본생성기-v3.5.3, 집 PC는 F:\projact\쇼츠대본생성기-v3.5.3이며, 두 코드베이스는 동기화되어 있음을 확인했다(집 PC에 1단계 패치들이 모두 반영되어 있었다).

2. 진단으로 확인한 핵심 사실
캐릭터 정체성의 단일 진실은 generated_scripts/characters/ 폴더이며, 각 캐릭터는 자신의 폴더 안에 front/angle45/back 이미지와 character.json(name, age, gender, face, hair, body, style 및 files 객체)을 가진다. 의상규칙의 텍스트 속성(이름/헤어/체형/스타일/의상핏)은 별도로 shortsLabCharacterRulesManager에 저장되며, labPromptBuilder가 이를 읽어 이미지 생성 프롬프트에 합성한다.

실제 생성 결과를 분석한 결과, 텍스트 속성(헤어/체형/의상)은 프롬프트에 정확히 들어가 일관성이 확보되지만, 가장 중요한 얼굴의 시각적 일관성은 확보되지 않음을 발견했다. 서버 로그에 [ImageAI] Reference files: 0이 찍혀, 3면도 합본 이미지가 단 한 장도 참조로 첨부되지 않고 있었기 때문이다. 특히 V4 자동 생성 흐름은 텍스트 프롬프트만 만들 뿐 3면도 첨부 기능과 완전히 분리되어 있었다.

3. 수행한 패치 (시간순)
3-1. 레이아웃 화면 채움 (반응형)
캐릭터 패널이 화면을 절반만 채우고 우측이 비는 문제를 해결했다. 원인은 외곽 컨테이너(ShortsLabPanel.tsx 7714라인)에 폭을 받는 클래스가 없어 내용 크기만큼만 차지한 것이었다. 해당 div의 클래스에 flex-1 min-w-0를 추가하여 부모의 남은 공간까지 끝까지 채우도록 변경했다. 이로써 좌우 분할(7870)과 캐릭터 패널의 lg:flex-1이 실제로 화면 끝까지 펼쳐졌다.

3-2. 유령 분석 결과 제거
캐릭터관리 탭에서 캐릭터를 선택하지 않았는데도 옛 얼굴 분석 결과(웃는 얼굴 사진 + 영문 프롬프트)가 떠 있던 문제를 해결했다. 원인은 컴포넌트 마운트 시 캐시에서 분석 결과를 자동 복원하는 로직(CharacterPanel.tsx 977 부근)이었다. face/hair/body의 추출 결과와 생성 이미지 6개 항목을 null로 복원하도록 바꿔 자동 복원을 차단했다. 단, 의상추출 탭은 별도 유지하기로 했으므로 outfit 관련 캐시 복원은 그대로 두었다.

3-3. 캐스팅 패널 숨김
기능이 3면도와 중복되어 혼란을 주던 캐릭터 캐스팅 패널을 화면에서 숨겼다. ShortsLabPanel.tsx에서 해당 패널을 감싸는 div의 className에 hidden을 추가했다. 코드는 남겨두되 화면에만 안 보이게 처리하여, 생성 로직의 캐스팅 참조가 깨지지 않게 했다.

3-4. 캐릭터 텍스트 저장 복구 (서버 POST)
가장 중요한 버그 수정이었다. 캐릭터의 헤어/체형/이름 등 텍스트를 수정하고 저장해도 새로고침하면 사라지는 문제가 있었다. 원인은 1단계 작업에서 POST /api/characters를 noop(아무것도 안 함)으로 막아두었기 때문이었다. 이는 localStorage 껍데기가 폴더 데이터를 덮어쓰는 것을 막으려던 조치였으나, 정당한 텍스트 수정까지 함께 막아버렸다.

server/index.js의 noop POST 블록(2067~2069)을 교체하여, 요청으로 들어온 캐릭터 중 폴더가 실제로 존재하는 캐릭터의 character.json 텍스트 필드(name, age, gender, face, hair, body, style, bodyTuning, identitySpec, description)만 갱신하도록 했다. 이미지 관련 필드(files/threeview/source)는 절대 건드리지 않으며, 폴더 없는 껍데기는 무시한다(기존 의도 유지).

이 패치는 명령어로 검증을 완료했다. 테스트용 가짜 캐릭터 폴더를 만들어 POST를 호출한 결과, 응답이 success: true, updated: 1로 정상 동작했고, character.json의 hair가 "old hair value"에서 "NEW hair value 새헤어"로 바뀌었으며 files 이미지 필드는 그대로 보존됨을 확인했다. 한글도 깨짐 없이 저장되었다.

3-5. 의상규칙 카드에 3면도 생성 기능 통합 (핵심 작업)
사용자 결정에 따라 캐릭터 관련 작업을 장르매니저 의상규칙 한곳으로 통일하기로 하고, 의상규칙의 각 캐릭터 카드에서 직접 3면도를 생성할 수 있게 만들었다.

먼저 의상규칙 UI의 위치를 특정했다. 미숙 화면에서 본 Name(Korean)/Identity/Hair/Body/Style/Outfit Fit 카드는 ShortsLabPanel.tsx의 12415~12470(여성)과 12613~12670(남성) 블록이며, characterRulesState.females.map으로 렌더링되고 updateCharacterRulesField로 텍스트를 수정함을 확인했다.

1단계로 3면도 생성 로직(상태 변수와 함수)을 추가했다. updateCharacterRulesField 정의(10969) 앞에, 캐릭터별 소스 이미지 맵, 생성 중 상태, 진행 표시 맵과 함께 handleRuleTurnaroundSourceUpload(사진 업로드)와 handleGenerateRuleTurnaround(3면도 생성) 함수를 삽입했다. 이 함수는 업로드한 기준 사진으로 Puppeteer 방식 엔드포인트(/api/image/ai-generate)를 호출해 정면/45도/뒷모습을 차례로 생성하고, save-character-turnaround로 캐릭터 폴더에 저장한다.

작업 중 한 차례 실패가 있었다. PowerShell here-string 안에서 템플릿 리터럴의 ${}와 백틱이 이스케이프 문제로 깨져 "Invalid character" 문법 에러가 다수 발생했다. 백업에서 즉시 복원한 뒤, 코드를 별도 텍스트 파일(__rule_turnaround_snippet.txt)에 먼저 쓰고 그 파일을 읽어 삽입하는 방식으로 바꿔 이스케이프 문제를 회피했다. 또한 이 파일은 useState를 직접 import해서 쓰므로(React.useState가 아님) 그에 맞춰 코드를 작성했다. 재삽입 후 문법 체크에서 내가 추가한 부분의 신규 에러가 없음을 확인했다(기존부터 있던 타입 경고들만 남음).

2단계로 UI를 추가했다. 각 여성 캐릭터 카드의 Outfit Fit 아래, 캐디 전용 블록({char.id === 'WomanD' && () 앞에 "3면도 생성(정면/45도/뒷모습)" 영역을 삽입했다. 이 영역은 기준 인물 사진 업로드 칸, 진행 상태 표시, "3면도 생성 후 저장" 버튼으로 구성된다. 해당 앵커가 파일에 2곳 있어 양쪽 모두에 삽입했고, 삽입된 버튼이 2개임과 신규 JSX 문법 에러가 없음을 확인했다.

4. 현재 상태
완료된 것은 다음과 같다. 폴더 기반 단일 진실(GET 폴더 스캔), 캐릭터 폴더 삭제(DELETE API, 정상 작동 확인), 텍스트 속성 영구 저장 복구(명령어 검증 완료), 레이아웃 화면 채움, 유령 분석 결과 제거, 캐스팅 패널 숨김, 그리고 의상규칙 캐릭터 카드에 3면도 생성 기능 통합(코드 삽입 및 문법 검증 완료).

5. 남은 작업
3면도 생성 UI가 브라우저에서 정상 표시되고 실제로 작동하는지(사진 업로드 → 생성 → 폴더 저장) 화면에서 검증해야 한다. 그리고 가장 중요한 미완성 과제로, 생성된 3면도 합본 이미지가 실제 이미지 생성 시 참조로 첨부되도록 연결하는 작업이 남아 있다(Reference files: 0 문제 해결). 이것이 캐릭터 얼굴 일관성의 핵심이다. 또한 검증 로직이 prompt 대신 processedPrompt를 보도록 고치는 작업(가짜 PERSON_COUNT_MISMATCH 에러 11개 제거), 캐디 슬롯의 나이/체형 데이터 오염 정리, 그리고 작동 확인 후 쇼츠랩 입력탭의 중복 캐릭터 탭(캐릭터선택/캐릭터관리) 정리가 남아 있다.
